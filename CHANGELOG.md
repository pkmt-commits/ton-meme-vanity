  CLI, dashboard and bot messages, issue and PR templates, CONTRIBUTING and SECURITY.
- Both web pages come in two languages: `docs/` (English) and `docs/ru/` (Russian), built from one template with strings

- `npm run telegram-setup` takes the first chat that messaged the bot (it used to prefer one hard-coded username).

## 1.1.0 — kernel v13: the score on the GPU, 2x faster, up to 4 addresses per key

- **The v5-lite sieve** (`cuda/v5lite.inc`): the GPU computes the v5 score itself, with the same word segmentation, the same
  dictionary (~47k words, `cuda/v5dict.h` from `src/gpu_dict_v5.mjs`) and the same weights. The old "word rules" passed
  ~25% of addresses scoring 150+ (measured on 200 million random addresses), v5-lite passes 99% at the same speed: about
  4x more good finds, and Node gets 20x fewer candidates. The `--v5t` flag (default `--save-min − 10`), the
  `ref/check_v5lite.mjs` check in setup, the measuring tools `src/recall_sample.mjs` / `src/recall_eval.mjs`, the kernel
  `flags` mode.
- **A 16-bit window** for the curve multiplication: a 60 MB table (`cuda/tbl16.bin`, generated by `npm run setup`), 16 point
  additions per key instead of 64. Keys and addresses are unchanged (import by seed is unaffected). Without the table the
  kernel uses the old path.
- **A dictionary index by three "runs"**: the word detector only tries matching words (+20–40%), with the same result as
  the reference (`validate`).
- **`--versions 1..4`**: W5, V4R2, V3R2 and V3R1 addresses are checked for one key almost for free (2 SHA-256 instead of a
  curve multiplication). MyTonWallet shows all four versions (Settings → Wallet Versions). ~2.2x more addresses per
  second than with W5 alone. The default is W5 only.
- Self-test: 100 comparisons with `@ton/ton` (4 versions, with and without the table).
- **TON Address Beauty** (`docs/index.html`, `npm run build:checker`): check any address with the v5 score right in the
  browser: hidden words and patterns, points, rarity ("1 in N"), a 10-second demo search. For GitHub Pages.
- **The in-browser generator** (`docs/generate.html`, `npm run build:generator`): search right in the browser, no GPU and
  no install. Keys come from `crypto.getRandomValues` and never leave the device. Fast key generation on tweetnacl
  (`web/keygen.js`: an 8-bit table + batched inversion, ~28k keys/s per core, 6x faster than noble), addresses of 4
  versions (`web/address.js`), a JS v5-lite prefilter (`web/lite.js`), a self-test against `@ton/ton` vectors on start.
  ~580k addresses/s on 15 threads of a Ryzen 7.
- Tested live: the generator on a phone, importing keys of all 4 versions into MyTonWallet (Wallet Versions).
- An English README: `README.en.md`.
- Security: randomness straight from the OS (`BCryptGenRandom` / `getrandom`) with checks; found seeds are wiped from GPU
  memory right after they are handed over, the base on exit (CUDA does not clear memory between processes);
  `.claude/settings.json` forbids Claude Code agents from reading key files; a warning about clipboard history.
- The kernel exits by itself if the wrapper dies (it could keep running as an orphan before).
- Wrapper: `gems.jsonl` is read as a stream (a file over ~512 MB used to crash the start), the kernel is restarted after
  a crash (up to 5 times an hour) with a Telegram message.

## 1.0.0 — first public version

- GPU kernel (CUDA): ed25519 + W5 (v5r1) address, a word/pattern sieve, a thermal regulator (NVML).
- Seed = `SHA-256(base ‖ counter)`: keys are independent of each other.
- The v5 score (frequency segmentation + bonuses for themes, separation, phrases, stretched letters, emoticons, meme numbers).
- Wrapper: every key re-checked with `@ton/ton`, `gems.jsonl`, a Telegram bot with 👍/😐/👎/⭐, a dashboard.
- `npm run setup` — one-command install; `npm run top` — finds without keys; `AGENTS.md` for AI agents.
